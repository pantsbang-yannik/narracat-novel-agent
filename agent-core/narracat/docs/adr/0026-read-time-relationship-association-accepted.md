# 间接关系读时现算，不入库固化

Status: accepted

## 背景

写作组装写作上下文包时，常需要把分散记录的事实关联成**间接关系**（B 师从 A、C 师从 A → B、C 是师兄弟）才能让写手写对人物关系。这种 2 跳关系当前没有被提供给写手：上下文包里的 `character_relationships` 只放正文明确写出、直接入库的关系边；图多跳（PPR）只在用户主动用 `novel_query` 提问时才跑，不进写作链路。一个自然的修法是让 memory-keeper 在每章入库时就把"师兄弟"推算出来、固化成一条新边——但小说里关系会翻转、会过期。

## 决策

需要推理/聚合才能得到的记忆（间接关系、跨实体聚合），**在写作组装时"读时现算"，不在 memory-keeper 入库时推理固化**。

具体落到 ④读时关联：在现有"对本章出场角色两两查直接关系"这一步，对**查不到直接边**的角色对补一道 **2 跳共邻、且只走截至本章仍有效的关系边**（复用现有出场角色对范围，不另立扳机、不做 N² 全员两两）。算出的派生关系**标注为"推断"**、收敛成人话、限条数、对枢纽/龙套共邻降权；**系统只负责把事实串到一起，称谓与语义判断交给写手**（不写关系组合规则表、不让系统给关系命名）。本次只做"关系型"关联，"状态聚合型"（主角现在欠谁的命、还有哪些未了结的梁子）记为同一能力的后续扩展。

## 为什么不固化（Considered Options）

- **写时固化（否）**：在一个事实不断翻转的世界里囤积派生数据，等于给自己埋下一致性炸弹——一条底层关系一变（C 叛出师门），就要回溯失效一大批派生边；而且它逼 memory-keeper（弱模型）做推断，正面撞 ADR-0013（别把薄推断锁成正史）与 ADR-0022（抽取只录明确写出的）。
- **纯靠写手 LLM 临场联想（否）**：写手手里只有两条独立的"师徒"事实，指望它自己联想到师兄弟不可靠，这正是当前的 gap。
- **读时现算（选）**：每次都基于"截至本章"的最新有效事实重算，关系反目了自然就不再说师兄弟——**天然防过期、防剧透**，且不污染记忆库、不逼弱模型推断。

## Consequences

- ④ 的正确性上限押在 **①抽取准确度** 与 **②失效标记正确性** 上（②的写/读双时间轴已由 ADR-0025 落地；①的抽取质量本次配套建合成集为主的分桶 eval 来守）。读时算解决的是"会不会漏推关系"（覆盖率），"关系数据本身准不准"（正确率）仍依赖地基。
- 派生关系标注为"推断"后，消费侧优先级为 **直接关系/章纲设定 > 派生关系**，冲突时派生让位。
- 远卷压缩（记忆"留不留得住"）是正交的另一条线，**不在本次范围**。
