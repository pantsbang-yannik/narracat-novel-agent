# ADR-0011: /write 生成端以第一稿阅读吸引力优先

**状态**: accepted（2026-05-30）

`/write` 生成端不再把 chapter-writer 的首要目标定义为字段合规、规则完整执行或审修通过，而是定义为**第一稿阅读吸引力**：正文必须立即好读、由场景推动、有情绪压力，并把读者带向下一章。保留 schema、小说目录结构和核心连续性合同不变，但重写 prompt 的字段消费方式：chapter-writer 先“找戏并放大”，outline 提供事件骨架而不是固定正文镜头表，metadata 是写完正文后的收尾合同，审修端 `reading_desire` 不回流成生成端 rubric。

## Considered Options

- **维持 ADR-0003 的字段式锚点拒写**：安全、可审查，但会把写手训练成 outline 检查员；在“剧情编排不错但正文难读”的问题上杠杆不足。
- **继续增加写作建议或反 AI 清单**：短期容易解释，但与 ADR-0006 / ADR-0009 的 craft-first 方向冲突，也容易让生成端回到过审思维。
- **阅读吸引力优先（采纳）**：牺牲一部分流程表单感，换取正文更像小说。硬边界仍保留：不偏离大纲核心事件，不破坏角色和世界连续性，输出完整 ChapterMetadata，不改非正文文件，不改 schema 和用户小说目录结构。

## Consequences

- chapter-writer 阶段零应从“字段具体度检查”改为“找戏并放大”；只在缺少任何可写场景材料时拒写。
- `outline.scenes[]` 约束事件骨架、压力点和结果，不约束正文开篇方式、镜头顺序和篇幅重心。
- `/write` Task 指令应成为任务 Envelope，只传当前章任务、WritingContextPack 和极短优先级提醒，不复述 agent 内部工作流。
- `narrator_voice` 应被蒸馏成本章叙述姿态；真人范例查询降为按需风格补救。
- `novel-craft` 主体应收敛为核心创作原则，长技法和编辑动作放到按需参考或审修/改写侧。
