# ADR-0015: 情绪承载温度——解除单一温度坍缩（accepted）

**日期**: 2026-06-01
**状态**: accepted
**触发**: dogfood「01-0531-novel」（archetype=言情沉浸）ch-001 通篇偏冷。定位发现：不是某条 prompt 偷偷作祟，而是一整条**自洽的冷链**——生成端配方、审美底色、审修门禁全部单向偏冷。

## 背景与问题

「情绪靠承载呈现（show 不 tell）」是 NarraCat 的北极星铁律，正确且必须保留。但实践中它被**窄化成只有"冷承载"**（减速、几不可察的微动作、留白），系统性地把所有情绪都写成"隔着一层"。冷链由多处叠加：

- `情感渲染.md` 第 8 条把「克制远比宣泄有力」设为情感最高美学，自查清单要求"最高潮处文字反而变短/变静"。
- `novel-craft §7.1` 的承载示例（折信压镇纸 / 笑着辞职 / 明知陷阱还去）**全是冷例**，缺热承载样板。
- `outline-architect` 模式 A 生成 `narrator_voice` 的 `reference_examples`/`tone`/`style_keywords` 时**自由 paraphrase**，LLM 对"言情"的默认联想（克制/暗恋/不说破）使其把 archetype 坍缩成单一冷温度；而这三个字段**不进 AskUserQuestion**（`plan.md`），用户无从否决。
- 审修端（continuity-editor / novel-antipattern）只罚"过热"（煽情/感叹号滥用/伪文学），**没有对称的"该热没热"检测**——温度门禁单向，必然收敛到冷。

结果：dogfood 项目即便选了"言情沉浸"，连释放章都会被写冷，且审修把这种冷判为"兑现成功"打高分。

## 决策

引入**情绪承载温度**概念（见 CONTEXT.md）：在 show-not-tell 框架内，承载有**冷/热两态**，两者都是 show、受同一条铁律约束（强度由动作/代价/不可逆选择度量，绝不靠命名情绪），区别只在温度。

- **保留** show-not-tell 与"不直说情绪"——防 AI 腔的核心资产不动。
- **解除**「克制 = 默认值 / 最高美学」这层跨 archetype 的审美底色（**单一温度坍缩**）。
- 温度由**场景张力 / 是否高潮释放**决定，不被 archetype 或全局克制审美钉死。**不动 archetype 分档**：悬疑冷叙仍冷（但高潮可炸）、言情沉浸恢复"该热则热"。

## 改动落点（减法 + 喂样板，非加门禁）

1. `情感渲染.md`：第 8 条改为"承载有冷热两态"；自查清单末条双向化；新增「冷承载/热承载」对照表。
2. `novel-craft §7.1`：show 词汇表补热承载样板（摔/拍/冲等有后果的动作），点破"克制不是默认值"。
3. `outline-architect` 模式 A：新增通用约束——`reference_examples`/`tone`/`style_keywords` 必须覆盖 archetype 冷热全谱，至少一条体现高潮/释放外放机制，禁止坍缩成单一冷温度。

## 与既有决策的关系

与 **ADR-0006**（生成端不注入负面反模式，避免"粉色大象"）**同向**：本次是在生成端**正向补"热承载"样板**，不是加禁令。与北极星纪律（提质量靠"拿掉噪声 + 喂真人范例"而非加门禁）一致——审修端**暂不新增**"该热没热"失分项（那是加检查），先靠生成端修正观察真稿。

## 验收

第 6 章（单元 climax 释放章）场景 2 做 A/B 真稿对照：唯一变量为 narrator_voice 配方冷/热，均喂改后承载知识。热配方在同一释放点写出"绷不住的笑、长舒一口气"的温度，**全靠有后果的动作承载（零 tell 形容词，不滑狗血）**，且保留言情沉浸的限知 + 克制底色（证明"解锁温度、不动分档"成立）；冷配方仍把释放写成"压住/不敢看"。改动方向验证通过。

## 暂缓 / 未覆盖（建议另立 issue）

- 审修端温度门禁单向（只罚过热）——待生成端修正后观察真稿，若仍给冷无脑高分，再**拿掉** narrator_appeal 评分指引里的克制偏向（仍是减法，非加门禁）。
- MCP `novel_query_style_reference` 语料库 corpus 的"情感渲染"类目选样偏克制——补真人热承载范例最治本，属数据层工作。
- 对话引号 `「」` vs `""`（独立的标点问题，与本 ADR 无关）。

## 可逆性

纯 prompt 改动，可逆（改回即恢复）。无 schema / 数据管线 / 写权限变更。
