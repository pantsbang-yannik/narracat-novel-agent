# NarraCat Agent Core 4.0 大爆炸重构 — 总设计（SSOT）

> 日期：2026-06-12 · 分支：test/no-continuity-editor · 版本目标：4.0.0
> 本文档是本次重构的**唯一权威规格**。所有实施 agent 以本文为准；与现存文件、历史 ADR、旧 CLAUDE.md 冲突时，以本文为准。
> 运行模型：DeepSeek v4 PRO（指令跟随弱于 Claude）。全部设计按弱模型假设：**代码能算的绝不让 LLM 填；LLM 只产正文/散文 + 最少判断性字段；一切结构化数据经 MCP 工具入口 ajv 校验，失败返回 errors[]+hint 重试 ≤2 次。**

## 0. 已拍板决策

| 决策点 | 结论 |
|---|---|
| 审校 | 双层最小审校：L0 代码机械层（唯一 FAIL 源之一）+ L1 客观错误极简 agent（≤100 行，5 类客观错误）；风格层主链彻底不审，/review 按需标注、永不回流 |
| 范例补热 | 不进本期。现有 corpus 保留照用，novel_query_style_reference 机制保留 |
| 机械化落点 | MCP 工具层为主，App 保持单长 run，App 联动最小化 |
| 节奏 | 大爆炸重写，完成后整体 dogfood 验收 |
| 记忆 | 分层记忆为主干 + 图谱-lite（受控谓词/别名归一），**否决**引入完整图谱引擎 |
| 兼容 | 存量项目不兼容（新架构新项目）；schema 推倒重建 v5，删除一切 deprecated/双形态 |
| enum 语言 | 全英文 snake_case，每个 enum ≤8 值；中文展示由渲染层负责 |
| 写权限模型 | 由「memory-keeper 唯一写权限」升级为「**每个 agent 只持有自己产物的提交工具**」（见 §4） |

## 1. 不变量（App 硬契约 — 任何实施不得破坏）

1. **目录与文件名**：`.narracat/ bible/ outline/ manuscript/ reviews/ notes/`；`manuscript/vol-VV/ch-NNN.md`、`outline/vol-VV/ch-NNN.md`、`outline/vol-VV/vol-outline.md`、`outline/master-outline.md`、`reviews/ch-NNN-review.md`、`bible/characters/{name}.md`、`bible/premise.md`、`bible/relationships.md`。
2. **state.yaml 字段集**（App GUI 状态机脊柱，字段名不动）：`progress.completed_chapters / total_chapters_planned / in_progress_chapter / last_completed_chapter`、`structure.total_volumes / total_chapters_planned / chapter_to_volume`、`word_count.total`、`checkpoint.last_command / last_step / timestamp`（checkpoint.last_command 写 `write ...` 形态）。
3. **command 文件名**：init / setup / reference / world / plan / write / review / rewrite / status 九个全保留。
4. **agent 文件名**：outline-architect / chapter-writer / continuity-editor / world-curator / memory-keeper 五个全保留（保名改内）。
5. **MCP 握手**：server 名 `plugin_narracat_novelmemory`、入口 `mcp-server/dist/index.js`、`NOVEL_CONFIG_PATH` env、config.yaml 的 `novel_id`。工具改名/新增必须同步 App `electron/main/orchestrator/sdk-runner.ts` 白名单（见 §11）。
6. **内容格式锚点**：章节大纲首行 `# 第N章 …`；master-outline.md 含 `## 叙述者腔调` 节（英文字段名 key: value 形态，供 `src/lib/narrator-voice.ts` 正则解析）；审校报告含 `审修结果: PASS` 或 `审修结果: FAIL` 一行。4.0 起这三者全部由 **MCP 工具机械渲染**，格式由代码保证。
7. **/write 步骤编号语义**（App recover-write.ts 硬编码镜像）：步骤 1=上下文聚合、3=正文生成、4=审修、5=修订、6=收尾入库。新 write.md 必须保持这套编号语义。
8. **templates/ 文件名**：`premise-template.md`、`relationships-template.md`（App novel-create.ts 复制它们）。内容可重写，文件必须存在。
9. **manifest**：旧 plugin 清单工件 name=`narracat`，version bump 到 4.0.0（同步 mcp-server/package.json 与 CLAUDE.md 基准行）。
10. Agent 写正文/大纲等用户可见 markdown 必须用 Write/Edit 工具（App 据此刷新 Workbench）；交互提问必须走 AskUserQuestion（App 问题卡）。

## 2. 目标架构总览

```
用户交互层  9 Commands（编排极简化，派发一律 Envelope 模式：只传路径+参数，不复述 agent 内部规则）
专业层      5 Agents（prompt 全部按弱模型重写：写手 ≤2k token；审校 ≤100 行）
引擎层      NovelMemory MCP（SQLite）：结构化落库唯一通道
            —— 每个 agent 持有且仅持有自己产物的提交工具
            —— 所有提交工具：ajv 校验 → 通过整体写入 / 失败返回 {errors:[{field,expected,actual,hint}]} → agent 自修正重试 ≤2 → 超限停在 checkpoint 报人工
机械层      hooks 全部 command 脚本化（产物存在性/receipt 核对）；一切渲染（outline md / review md / 叙述者腔调节）由工具从已验证数据生成
```

**创作哲学（继承北极星，写进新 CLAUDE.md）**：第一稿阅读吸引力是唯一目标；拿掉噪声 + 信任模型 + 喂真人范例，而非加规则/门禁/检查；真稿验收，不以 prompt 行数验收；克制类校准必须成对声明对边——但 4.0 的解法是**根本不写克制类校准**。

## 5. Schema v5（schemas/ 全部重写）

通用纪律：零 deprecated、零 oneOf 双形态、零版本演化史 description、enum 全英文 ≤8 值、单工具单次提交对象叶子字段 ≤15、description 只写现行规则。

### 5.1 outline-structure v5

- 书级：`central_dramatic_question, protagonist_core_desire, protagonist_core_lack, antagonistic_force, stakes_progression`（引擎 5 字段保留）+ `storylines[]`（§3.1 字段）+ `foreshadowing_registry[]`（预算核验）+ `volumes[]`。**narrator_voice 移出**（归设定层，见 §7 setup；master-outline.md 的腔调节由渲染器从 bible 数据生成）。
- 卷级：`volume_no, title, arc_list[], dilemma_milestone?`（全书里程碑制替代「每卷升一级」：50% 处达 value、末段达 identity/existential，validator 按里程碑校验）。
- arc 层（替代 units，10-40 章网文副本粒度，按 tier 伸缩）：`arc_id, title, chapter_start, chapter_end, core_question, irreversible_change, next_arc_seed, payoff_beats[]`。
- `payoff_beats` enum：`face_slap, level_up, windfall, fame, reveal, reunion, counterattack, sweet`（章级爽点显式化，每 arc 按预算）。
- 章级（required ≤9）：`chapter, title, value_shift, emotional_stakes, dramatic_focus, storyline_focus[], scenes[2-4]{location, characters, pressure_point}, ending_note?, foreshadowing_touch[]?`。删除 summary/key_events/characters_involved/tension_level 等全部弃用字段及双命名。

### 5.2 结构预算公式（novel_get_structure_budget，代码实现）

```
tier: S ≤ 60万字 | M ≤150万 | L ≤300万 | XL > 300万
volumes        = ceil(total_chapters / clamp(60, 40..80))
arc_span       = S:5-15章  M:10-25  L:15-35  XL:20-40
storyline_budget = clamp(floor(总字数万 / 50), 2 .. 8)
foreshadowing  = major ≈ volumes, medium ≈ arcs, small ≈ total_chapters/10
iconic_scenes  = 2-3 / volume；turning_points = 3 / volume
payoff_beats   = ≥1 / arc（S 档可 0）
```
预算进 plan 派发指令并进 validator 数字下限（替代「≥5 条」常数）。XL 档阶段一只产书级骨架+第一卷，后续卷 earliest-missing 推进（伏笔 target_reveal 允许 `vol-08` 卷级粗锚点）。

### 5.3 其他 schema

- chapter-metadata.json：**删除**（被 novel_commit_chapter 参数取代；写手不再产任何元数据，HTML 注释通道整体废除）。
- review-report.json：重写为 novel_submit_review 的参数 schema（§4.1，6 字段）。
- memory-extraction.json：复活为 novel_submit_extraction 参数 schema。
- writing-context-pack.json：v2（§6）。
- foreshadowing-system.json：保留，清理 deprecated。
- cascade-impact-report.json：保留（3 必填字段，/rewrite 用）。

## 6. WritingContextPack v2（builder 升级）

总预算 10-12k token，builder 内硬截断 + warnings。组成：

| 区块 | 预算 | 来源 |
|---|---|---|
| 本章细纲全文 | ~3k | outline 文件（机械渲染产物，无反解析风险） |
| 世界规则（world_rules） | ~0.7k | bible/premise.md 立项卡 card 7 机械抽取；写手与审校核对「设定违背」的权威依据（写手无 MCP 查询，规则必须随包注入） |
| 风格指令（一段自然语言） | ~0.8k | builder 由 narrator_voice（bible 数据）+ style_profile 档位渲染；写手零分支消费 |
| 真人范例 2-3 段（带机制注解） | ~1.2k | corpus 按 genre/scene 选取（现有库） |
| L1 热层：前 3 章 brief+锚点 | ~2k | chapter_summaries |
| L2 温层：本卷已完成 arc 摘要 + 各前卷摘要 | ~2k | arc_summaries |
| 角色状态卡（本章出场） | ~1.5k | character_cards + 本章动线 |
| 伏笔 due-list | ~0.5k | major 全部 + medium 限本卷 + small 限本 arc + target ≤ N+10 临期；其余只给 count |
| storyline 聚焦 + 缺席预警 | ~0.3k | chapter_storyline_focus SQL（某线连续 ≥5 章无 focus → warning） |
| 语义检索 top5 | ~0.8k | §3.3 多查询 hybrid |

`style_profile`（config.yaml 新增，setup 写入）：`web_fast | web_standard | literary` 三档，决定风格指令里的钩子密度/短句容忍/情绪直给水位描述。默认 web_standard。

## 7. Commands 规格

**通用**：派发一律 Envelope（章号/路径/参数，不复述 agent 规则）；一切「正则提取/JSON.parse/计数」从 prompt 删除，改调工具；每步完成调 `novel_checkpoint`。

- **init**：瘦身为纯机械（目录/config/MCP 自检 + 复制模板）。书名/题材语义并入 setup 对话。
- **setup（完全重写，P1 核心）**：grill 式对话立项。开场让用户自由倒点子（一句话到三千字均可）→ 一次只问一个问题、每问附自己的推荐答案、问题由上一个回答驱动（无固定题数/题序）、追模糊与矛盾处、能从 reference-guidance 推出的不问 → 对关键决策给 2-3 个差异化方案对比（AskUserQuestion 仅用于真二选一）→ 收束为**网文立项卡**逐张确认落盘 bible/premise.md：①题材读者契约（细分题材+读者默认期待+本书超预期点+情绪基调）②核心钩子（黄金三章承诺）③金手指/爽点引擎（能力+限制+成长性+反馈回路+为何不破坏冲突）④主角欲望-代价卡（表层想要/深层需要/付出代价/底线 → 直出 protagonist_core_desire/core_lack）⑤对抗力量 ⑥中心戏剧问题 ⑦世界规则可冲突性（每条规则答「让谁和谁打起来」）⑧叙述声音（archetype+基调，存 bible，渲染期供 master-outline 腔调节）⑨留白声明（canon/暂定/留白三级）。篇幅与每章字数在此一并收集写 config.yaml（estimated_total_chapters/words_per_chapter/style_profile）。立项卡即 premise.md 新模板（templates/premise-template.md 同步重写）。
- **world（重写）**：支持一次对话批量立项（主角+反派+体系同会话产草案）；6 维度池降级为 world-curator 合成时的完备性检查清单（缺维度标「留白」，不逐题问询）；conflicts[] blocking 逐条确认保留；「直接帮我定」快进保留。
- **plan（重写，目标 ≤250 行）**：步骤＝读立项卡 → `novel_get_structure_budget` → 派发 outline-architect（Envelope：预算表+引擎字段）→ architect 自调 `novel_submit_outline / novel_submit_chapter_outline` 提交（含自修正重试）→ 主会话只读回执与 earliest-missing 推进。narrator_voice 流程整块删除（归 setup）。

## 8. Agents 规格

### 8.1 chapter-writer（全文草案，实施按此落地，允许 ±10% 措辞润色，禁止增加任何规则）

```markdown
---
name: chapter-writer
description: Writes novel chapters with maximum reading appeal, strictly following the chapter outline and continuity context.
tools: Read, Write
---

你是这部小说的写手。你唯一的目标：写出让读者**忍不住读下去**的一章。

## 工作方式

1. Read 任务里给你的 WritingContextPack 文件（唯一上下文来源，不要凭记忆补）。
2. 找到本章最有戏的一刻——细纲里 dramatic_focus 指向的那个瞬间。整章为它服务：把它放大写透，给足动作、代价和不可逆的变化。
3. 直接写。按「风格指令」一段所描述的腔调与温度写：该热就热——爽点直给、情绪外放、排比金句在热场景是一等写法；该冷就冷。范例段落展示了什么叫好，学它的机制，不抄它的句子。
4. 情绪用动作、代价和选择来承载，少贴情绪标签。
5. 章末要有一个有意的收尾：新麻烦、未解的问题、情绪悬在高点，或一个值得停留的画面。不要总结全章。

## 硬约束（仅此 5 条）

1. 细纲的核心事件走向为真：scenes 的压力点要发生，value_shift 要兑现。可以重排场景顺序，不可改变事件结果。
2. WritingContextPack 里的 continuity 预警逐条回应：与前文矛盾的写法不能出现。
3. 字数落在任务给定区间。
4. 产出只有一个文件：把正文写入任务指定的 manuscript 路径。第一行就是小说正文（可含章节标题行），文件里不写任何说明、元数据或注释。
5. 不创建、不修改任何其他文件。

## 上下文不可用时

WritingContextPack 路径读不到或 JSON 解析失败：停止，报告问题，不要凭记忆写。
细纲只有抽象概括、没有可写的具体场景：停止，报告「细纲不可写」，建议先跑 /narracat:plan。
```

frontmatter 无 skills（builder 已把范例与风格渲染进 WCP）。**禁止**出现：数值处方、自检问卷、手法轮换、对冲条款、「克制/留白/收敛」类词汇。

### 8.2 continuity-editor（L1 客观错误审校，≤100 行）

- tools: Read + `novel_submit_review`（唯一写）+ 少量读工具（novel_character_state / novel_foreshadowing_density）。
- 无任何 skills 注入。输入：WCP + manuscript。只查 **5 类客观错误**，每发现一条按 `{severity, where, what, fix_hint}` 收集：
  1. 连续性矛盾（角色状态/时间线/已立事实，对照 WCP）→ blocker
  2. 设定违背（世界规则/能力边界，对照 WCP 设定区）→ blocker
  3. 锚点未兑现（binary：细纲 dramatic_focus 的核心戏在正文**可识别/不可识别**；不判放写程度）→ blocker
  4. 伏笔合同（due-list 中本章应触达未触达）→ blocker
  5. 物理不可能（动作/空间在物理层不成立且非梦境/规则设定）→ blocker
- 其他一切（风格/节奏/腔调/丰盛度）**不在职责内，不得报告**。可疑但不确定的事项报 note（不影响 verdict）。
- 产出 = 调 `novel_submit_review` 一次。不写任何文件（报告由工具渲染）。校验失败按 hint 修正重试。

### 8.3 memory-keeper

只做两件需要理解的事：①叙事摘要+锚点+「可继续写的戏」（→ `novel_commit_chapter`）②事实变更清单（→ `novel_submit_extraction`，受控谓词）。arc/卷边界时 ③压缩摘要（→ `novel_consolidate`）。全部散调写工具指令、14 步清单、五扇区分类删除。保留丰盛原则压缩为 3 行（具体动作/代价/未解压力，禁标签化摘要）。

### 8.4 outline-architect

输入：Envelope（引擎字段+预算表+earliest-missing 区间）。产出经 `novel_submit_outline` / `novel_submit_chapter_outline` 自行提交，按 errors[].hint 自修正 ≤2 次。skills: novel-structure（瘦身版）。prompt 目标 ≤200 行：身份、三层产物职责（书/卷+arc/章）、预算表消费方式、三件套（core_question/irreversible_change/next_arc_seed）质量要求、payoff_beats 编排、提交流程。

### 8.5 world-curator

合成+冲突检测一次调用；6 维度池作为完备性检查清单（缺则标留白）；ADR-0013 不编造纪律保留。prompt ≤120 行。
