# NarraCat 小说写作系统审计报告

> 审计日期：2026-03-28
> 审计范围：全系统（5 Agent + 5 Skill + 8 Command + 6 Schema + hooks + templates）
> 审计目标：诊断系统性模版化根因，提出可落地的优化方案
> 背景：系统已产出 7 部小说，呈现跨作品的同质化问题

---

## 第一部分：系统性问题诊断

### 1. 对话呈现形式单一（严重度：极高）

**现象：** 90%+ 的对话以裸引号形式呈现——`"台词。"` 独立成句，偶尔前缀 `XX说`。缺少动作先行、神态夹入、心理穿插、场景融入等多种对话呈现形式。

**根因定位：**
- novel-craft §1.3 "动态化"只有一句话："对话中穿插动作、表情、环境反应"——这是一条淹没在 7 条要点中的规则，而不是核心写作技法
- 整个系统对"对话密度"（百分比）有精确控制，但对"对话呈现形式"（物理排版方式）完全无指导
- chapter-writer 的上下文中有 26 条反模式 + 6 道门禁要避开，模型的认知预算被合规检查占满，默认走最安全路径——裸引号对话
- speech_pattern 字段关注的是角色"说什么样的话"（内容差异化），而非"对话在页面上如何呈现"（形式差异化）

**为什么导致模版化：** 当每段对话都是 `"台词。"` → 叙述 → `"台词。"` 的固定节奏，读者会感觉所有场景的对话"长一个样"，即便角色说的话内容不同。

**如何验证：** 从任意两部小说各取 5 章，统计对话呈现形式的分布——裸引号、动作先行、神态夹入、心理穿插、无引号内心转述等各占多少比例。

**如何修改：** 在 novel-craft §1 新增"对话呈现技法"专节，给出 6-8 种具名技法和示例（见第四部分详案）。

---

### 2. 开篇手法趋同（严重度：高）

**现象：** 不同小说、不同章节的开篇呈现高度相似的节奏和切入方式。

**根因定位：**
- 2.3.0 删除了 `opening_type` 枚举轮换机制，替换为 novel-structure §4.1 的"原则性判断"
- §4.1 只列了 5 个开篇类型名称（事件闯入、对话切入、行动跟随、感官氛围、时空跳跃），无任何示例
- continuity-editor 的"结构重复预警"是被动检测（检查前3章是否雷同），但这个信息传递到 chapter-writer 时只是 `continuity_warnings` 中的一条文本警告——既不具体也不强制
- WritingContextPack 中没有"前 N 章实际使用的开篇手法"字段，chapter-writer 无法感知自己在重复

**为什么导致模版化：** 模型有"舒适区"开篇（通常是环境感知 + 角色内心状态），没有外部信号打破这个默认值，它会一直用同一种方式开篇。

**如何验证：** 提取 20 章的首段，人工分类开篇手法，统计分布。

**如何修改：**
1. continuity-editor 预检时提取前 3 章的实际开篇技法描述（不是枚举值，是一句话描述）
2. 写入 WritingContextPack 的新字段 `recent_openings`
3. chapter-writer 看到具体的前文开篇后，有信息基础来主动回避

---

### 3. 结尾模式固化（严重度：高）

**现象：** 章节结尾呈现相似的"悬念钩子"节奏——几乎都是"新信息揭示"或"角色行动暗示"两种。

**根因定位：**
- `ending_type` 枚举同样在 2.3.0 被删除
- novel-antipattern H1/H2 定义了"不能做什么"（不总结升华、必须有钩子）
- 但"钩子"的定义极为狭窄：rubric.md 定义 = "新麻烦/代价显现/误会加深/新目标/未兑现承诺"——这 5 种已经是全部选项
- chapter-writer 为了通过 GATE-5（段末/章末无点题总结且有钩子），会机械地在结尾安插一个信息悬念
- 更重要的是：这个系统没有教模型"好的结尾还可以是什么"——情绪留白、行为回声、意象收束、日常细节中的裂缝、对话戛然而止等丰富手法都不在系统词汇里

**为什么导致模版化：** 当结尾的合法选项只有 5 种，而系统又强制要求必须有钩子，结果就是所有结尾都是同一种"悬念式收尾"。

**如何验证：** 提取 20 章的末段，分类结尾手法。

---

### 4. 叙述模式单一（严重度：极高）

**现象：** 全篇使用同一种叙述模式——"第三人称限制视角 + 全景叙述 + 穿插内心活动"。缺乏叙述模式的切换和变化。

**根因定位：** 这是系统中最大的隐性盲区——**整个系统没有"叙述模式"的概念。**

现代小说叙事至少有以下模式可以在一章之内切换：
- **场景模式（Scenic）**：实时展开，像摄像机跟拍
- **概述模式（Summary）**：压缩时间，快速推进
- **自由间接话语（Free Indirect Discourse）**：叙述者声音和角色声音融合
- **内心独白（Interior Monologue）**：纯角色意识流
- **描写停顿（Descriptive Pause）**：时间暂停，细致描写
- **评论模式（Commentary）**：叙述者发表观点（某些风格中合法）

NarraCat 系统的所有规则都假设一种单一叙述模式。novel-craft 谈的是"对话/角色/信息控制/展示技法/声音/戏剧力"——都是关于"写什么"和"怎么展示"，而不是"用什么叙述姿态来讲"。

**为什么导致模版化：** 叙述模式单一是读者"感觉像同一个人写的"的最深层原因。不同段落、不同场景如果都用同一种叙述姿态，文字的质地就无法变化。

---

### 5. 场景描写薄弱且同质（严重度：高）

**现象：** 场景描写要么缺失（为避免 D1"描写不负重"），要么使用相似的感官套路（视觉 + 声音 + 气味的固定三件套）。

**根因定位：**
- novel-antipattern D1 要求"每段描写必须回答'它如何改变选择/制造阻碍/暴露风险'"——这是一个极高标准，导致模型宁可不描写也不冒"无用描写"的风险
- D4 禁止"通用意象套件"（微风/光影/尘埃/心跳/指尖发凉），但没有提供替代品
- 整个系统没有"场景质感"的正面指导——怎么用独特的感官细节构建空间感、怎么用环境暗示角色心理、怎么用物理空间创造叙事张力
- novel-craft §1.4 "场景调度"只有 5 行，关注的是"谁在哪里"的空间位置，不是"场景怎么活起来"

**为什么导致模版化：** 描写是最能体现作者个性的维度。当系统把描写压缩到"功能性最低限度"，小说就失去了质感和辨识度。

---

### 6. 情绪表达公式化（严重度：高）

**现象：** 情绪展示高度依赖"物理动作 + 身体反应"公式——攥拳、咬唇、呼吸变重、手心出汗。

**根因定位：**
- novel-craft §4.1 给出的公式 = "可见动作 + 约束 + 微小后果"——这本身就是一个模板
- novel-antipattern E1/E2 + GATE-4 联合施压：200 字内 >=3 情绪词即触发门禁
- 模型为避免情绪词，只能用物理动作替代——但物理动作的词汇表有限（人体能做的外显动作也就那么多）
- novel-craft §5.3 提到"用角色特有的微观反应替代通用身体信号"，但这只是一条指导原则，没有技法库

**缺失的情绪表达技法：**
- 通过环境感知变化暗示情绪（角色视角中世界的变化）
- 通过时间感知变化（时间突然变快/变慢/停滞）
- 通过注意力焦点的异常（注意到不该注意的细节）
- 通过语言变化（说话方式改变、突然沉默、话题转移）
- 通过行为逻辑的断裂（做出与当前情境不匹配的事）
- 通过叙述节奏变化（段落突然变短/变长、句式碎裂/拉长）

---

### 7. 人物塑造的"规格化"（严重度：中高）

**现象：** 角色在设定层面有差异（不同的性格、语言指纹、核心矛盾），但在实际文本中的行为模式趋同——都是"观察 -> 判断 -> 克制 -> 行动"的标准流程。

**根因定位：**
- 角色档案的结构化模板（character-template.md）用统一格式描述所有角色，这本身就在推向标准化
- WritingContextPack 将角色压缩为 JSON 字段（current_goal, fear_or_risk, stance, speech_pattern），chapter-writer 看到的是结构化数据而非活生生的人
- 系统中"角色差异化"的执行完全依赖 speech_pattern 和 inner_conflict 两个文本字段——但它们在 JSON 上下文包中只是几十个字的描述
- 更关键的问题：**角色的思维方式、决策逻辑、价值排序都没有系统性建模。** 语言指纹解决了"说话像谁"，但没有解决"思考像谁"

---

### 8. 情节推进的"事件串联"模式（严重度：中高）

**现象：** 情节推进呈现"事件A -> 反应 -> 事件B -> 反应 -> 事件C"的均匀节奏。缺乏节奏变化——有时应该加速（蒙太奇式快进），有时应该减速（一个瞬间展开 500 字），有时应该跳跃（省略 + 留白）。

**根因定位：**
- GATE-1 要求"任意连续 300 字内必须有状态改变事件"——这是一个恒定密度要求
- 但好的小说节奏是波浪形的：高密度段 -> 留白段 -> 加速段 -> 定格段。恒定密度 = 没有节奏
- novel-structure §1.2 在大纲层面讲"压抑-释放"，但在章节内部没有对应的节奏变化指导
- chapter-writer 的字数控制（2000-2500 默认）加上事件密度要求，等于强制要求在固定篇幅内塞入固定数量的事件——节奏变化的空间被压死了

---

### 9. 冲突升级方式单一（严重度：中）

**现象：** 冲突模式集中在"信息揭示"和"直接对峙"两种，缺少暗中博弈、错位冲突、价值观碰撞等更丰富的形态。

**根因定位：**
- novel-craft §6.1 说"冲突要升温"，但只描述了一种冲突形态：两人之间温度升高
- novel-structure §8.2 定义了冲突五阶段（对比 -> 反差 -> 冲突 -> 转折 -> 和解），这是大纲级追踪工具，不是执行级技法
- 系统中缺少"冲突类型词汇表"——执行层面的冲突可以是：
  - 目标冲突（双方想要同一个东西）
  - 价值观冲突（对"正确"的定义不同）
  - 信息不对称冲突（基于误解的对抗）
  - 义务冲突（两个承诺不可兼得）
  - 身份冲突（角色与自己的战争）
  - 资源冲突（物理限制造成的对抗）
  - 时间冲突（来不及了）

---

### 10. 语言纹理与辨识度缺失（严重度：极高）

**现象：** 7 部小说读起来像"同一个系统写出来的不同故事"——语言本身没有辨识度。

**根因定位：** 这是所有上述问题的综合效应，但有一个独立的结构性原因：

**系统声音压倒项目声音。** 每部小说共享同一套 Skill 注入（novel-antipattern ~135行 + novel-craft ~143行），这些规则构成了一个强烈的"系统审美偏好"。style_guidance 字段试图提供项目级个性化，但它只有 ~10 个字段、~200 字的文本量。与 ~300 行的系统规则相比，项目个性化信号太弱了。

换算成认知权重：系统声音 : 项目声音 约等于 5:1。模型写出来的不是"这部小说的声音"，而是"NarraCat 系统的声音"。

## 第二部分：根因分析

按影响力排序：

### 根因 1：约束-引导比例严重失衡（总控层 + Skill 层）

| 类型 | 行数（估算） | 条目数 |
|------|-------------|--------|
| 反模式规则（不要做什么） | ~135 行 | 26 子项 + 6 门禁 |
| 黑名单词表 | ~120 行 | 100+ 模式 |
| 评分量表 | ~80 行 | 8 维度 |
| 正面写作指导（应该做什么） | ~143 行 | ~30 条 |
| 声音与个性（怎么写得独特） | ~25 行 | 4 条 |

系统花 ~335 行教模型"不要做什么"，只花 ~25 行教它"怎么写得独特"。这个比例决定了模型的认知分配：绝大部分注意力用于合规，几乎没有注意力用于创新。

**这是最核心的根因。** 它不是某个规则的问题，而是整个系统设计哲学的问题——把写作当成了合规问题而非创造问题。

### 根因 2：正面技法库严重不足（Skill 层）

系统知道"不要裸引号对话"但不知道还有什么对话呈现方式；知道"不要通用意象"但不知道什么样的意象是好的；知道"不要短句堆砌"但不知道丰富的句式变化有哪些。

缺失的技法维度：
- 对话呈现形式（6-8 种）
- 叙述模式切换（5-6 种）
- 场景质感构建（感官维度 + 空间动力学）
- 情绪表达多样化（超越物理动作）
- 段落结构变化（不只是句式变化）
- 时间处理技法（加速/减速/定格/跳跃）

### 根因 3：WritingContextPack 的结构化传递消解了创作信号（数据管线层）

角色从"活的人"变成了 JSON 字段——`current_goal: "找到真相"`, `fear_or_risk: "暴露身份"`, `stance: "谨慎试探"`。这些精确的标签在传递信息的同时消解了丰富性。chapter-writer 看到的是要执行的"参数"，而不是一个需要理解和共情的角色。

同样的问题出现在大纲传递中：`value_shift: "信任->怀疑"`, `emotional_stakes: "可能失去唯一的盟友"` 是精确的规划语言，但精确本身就是枷锁——它给了结果，不给过程的自由度。

### 根因 4：continuity-editor 同时控制输入和输出（Agent 分工层）

continuity-editor 既是"上下文组装者"（预检模式），又是"质量裁判"（审修模式）。这意味着：
1. 它按自己的理解组装输入（什么信息重要、什么信息省略）
2. chapter-writer 基于这个输入创作
3. continuity-editor 再用自己的标准评判输出

这是一个闭环：裁判同时是教练，系统收敛于裁判的审美偏好。而裁判的审美偏好 = 26 条反模式 + 6 道门禁 + 8 维度评分——一套合规性审美。

### 根因 5：记忆系统反馈模版化语言（记忆层）

memory-keeper 将每章压缩为 200-500 字摘要 + 事实三元组。这些结构化的记忆通过 `recent_summaries` 回灌到下一章的 WritingContextPack。当 chapter-writer 看到的"前情"是结构化摘要而非生动的叙事片段时，它产出的延续自然也偏向结构化。

尽管 2.1.0 修复了 memory-keeper 的"模板化语言"问题，但问题更深：**摘要这种形式本身就是对叙事丰富性的压缩。** 三元组 `(张三, 身份, 禁军统领)` 在信息层是准确的，但它把一个有血肉的角色变成了数据库条目。

### 根因 6：质检标准以"无缺陷"为目标而非"有灵气"为目标（质检层）

审修的判定逻辑：
- 任一维度 FAIL -> FAIL
- 有 MINOR -> REVISE
- 零问题 -> PASS

注意：PASS 的标准是"零问题"，不是"有亮点"。系统没有任何机制来奖励精彩——只有惩罚缺陷。这直接鼓励保守写作：一篇没有缺陷但也没有灵气的文章比一篇有一处冒险但某个门禁触发的文章评分更高。

### 根因 7：风格指南的定义力不足（风格层）

style-guide-template.md 提供了 9 个维度的空白模板。setup 命令通过引导式对话填充这些字段。但填充的结果是标签式的描述（如 `文风方向: 写实`、`节奏要求: 张弛有度`），这些描述太抽象，无法真正塑造文本风格。

对比人类编辑给作者的风格指导："你的这一段好，因为..."、"这个句子的节奏可以参考 XXX 作者的写法..."、"这部小说的声音应该像 XXX 但更 XXX"。人类用例子和感觉传递风格，系统用标签传递——标签是风格的影子，不是风格本身。

## 第三部分：是否"过度约束"？

**明确回答：是的，系统存在严重的过度约束问题。**

但过度约束不是均匀的——某些维度约束过度，某些维度约束不足，某些维度约束方式错误。

### 最伤害灵气的约束（建议大幅放松或重新设计）

| 约束 | 当前状态 | 伤害机制 | 建议 |
|------|---------|---------|------|
| GATE-1: 300 字无事件 | 硬门禁 | 禁止节奏留白，强制恒定密度 | 放松为 500 字，且允许"有意减速段"例外 |
| GATE-6: 形容词拆列 >=2 处 | 硬门禁 | 微管理句式，某些风格中"冷的，硬的，沉的"是合法的文体选择 | 降为软警告 |
| D1: 描写不负重 | 重级反模式 | 扼杀场景质感，模型宁可不写描写 | 重新定义为"独立描写段 >=150 字时需负重"，短描写不检查 |
| D3: 空洞环境开篇 | 中级反模式 | 禁止了一种合法的开篇选择 | 删除。开篇多样性应通过正面引导而非负面禁止来实现 |
| A5: 连接词过密 | 中级反模式 | 在叙述型文风中，"于是/然而/同时"是正常连接 | 降为弱警告，仅在 200 字内 >=4 次同一连接词时触发 |
| 修辞节奏: 连续 3 段不得每段有修辞 | chapter-writer 硬规则 | 机械化的修辞分配要求 | 删除。修辞密度应由 style_guidance 控制，不同风格有不同修辞密度 |
| "按下不表"<=2 次 | chapter-writer 硬规则 | 合理但过于具体的计数限制 | 保留原则但删除计数 |
| 字数 2000-2500 默认 | init 配置 | 强制均匀篇幅，某些章节天然需要长或短 | 改为目标中值 + 弹性范围（如 2000-3500） |

### 应保留的约束

| 约束 | 理由 |
|------|------|
| GATE-2: 对话信息倾倒 >40% | 防止最严重的 AI 对话问题 |
| GATE-5: 总结升华封口 | 防止最明显的 AI 结尾问题 |
| 铁律 1: 大纲核心事件不偏离 | 保证长篇连续性的基础 |
| 铁律 2: 场景必须有事件骨架 | 保证基本叙事质量 |
| value_shift 要求 | 保证每章有叙事意义 |
| 伏笔兑现检查 | 长篇创作的必要工程约束 |

### 应彻底删除的约束

| 约束 | 理由 |
|------|------|
| GATE-6（形容词拆列 >=2 处） | 过度微管理，风格依赖 |
| D3（空洞环境开篇） | 环境开篇本身不是问题，无变化才是问题 |
| F2（同义词机械轮换） | 判定标准模糊，误杀率高 |
| 黑名单中大量"出现即审视"条目 | 信号过多 = 噪音，模型无法区分轻重 |

### 约束方式错误的（需重新设计而非删除）

| 约束 | 问题 | 重新设计方向 |
|------|------|-------------|
| 反模式 26 子项全量注入 | 信息过载，模型无法全部兼顾 | 分层：核心 10 条全量注入，其余 16 条移入 references/ 按需检查 |
| blacklist 100+ 模式 | chapter-writer 没有能力在创作时实时检查 | blacklist 只注入 continuity-editor，chapter-writer 只看核心铁律 |
| evaluation_focus 动态维度 | 好的设计，但维度全部是"检查 XX"，没有"尝试 XX" | 加入正面维度——"本章尝试一种新的对话呈现方式"、"本章描写中使用至少一个独特感官细节" |

### P0-A：对话呈现技法库

**位置：** novel-craft §1 新增 §1.5 "对话呈现形式（Dialogue Rendering）"

**内容框架：**

```markdown
#### 1.5 对话呈现形式

对话在页面上的物理呈现方式决定了阅读体感。以下 7 种技法应在一章中交替使用，避免单一形式主导。

**T1 动作先行** — 先写动作，台词从动作中流出
> 他搁下筷子。"你说的不对。"

**T2 神态夹入** — 台词中间插入神态/动作，制造节奏断裂
> "你说的——"她咬了一下嘴唇，"不对。"

**T3 心理穿插** — 台词后紧接内心反应，揭示潜台词
> "没事。"但她手指在桌面下攥了一下。

**T4 场景融合** — 环境与台词交织，场景参与对话
> 窗外的雷声正好在这时响了。"你说的不对。"他得把声音提高一倍。

**T5 无标注裸对话** — 省略说话人标识，靠上下文和语言指纹辨认
> "走不走？"
> "你先说。"
> "我问你。"
>（适用于双人对话、节奏快速、角色声音已建立的场景。连续无标注不超过 4 轮。）

**T6 动作替代台词** — 用行为代替语言回应
> "你到底怎么想的？"
> 他把钥匙放在桌上，关门出去了。

**T7 转述与间接引语** — 不用引号，用叙述者声音转述对话内容
> 她花了半个小时解释来龙去脉，从那封信开始说起，说到最后自己也觉得荒唐。

一章中对话呈现应至少覆盖 3 种以上技法。裸引号直接对话（"台词。"XX说。）全章占比不超过 40%。
```

**联动修改：**
- chapter-writer 戏剧力准则第 5 条"角色要有自己的话" -> 扩展为"角色要有自己的话和自己的说话方式"，引用 §1.5
- continuity-editor 审修"角色一致性"维度增加"对话呈现多样性"检查项
- evaluation_focus 新增映射：active_characters >=2 -> "对话呈现多样性"(standard)

### P0-B：约束表面积削减

**目标：** 将 chapter-writer 直接接触的约束从 ~300 行削减到 ~150 行。

**方法 1：反模式分层**

将 novel-antipattern 26 子项分为两层：

- **扩展层（16 条，移入 references/extended-patterns.md）：** A3, A4, A5, A6, B2, B4, B5, C3, D1, D2, D3, D4, D5, E1, F1, F2, I1, I2

- 审修端的检查能力不受影响（扩展层 + blacklist 在审修时全量可用）

### P1-A：叙述模式技法库

**位置：** novel-craft 新增 §7 "叙述模式（Narrative Modes）"

**内容框架：**

```markdown
### 七、叙述模式（Narrative Modes）

一章之内不应只有一种叙述姿态。以下 5 种模式的切换构成叙事的"呼吸"。

#### 7.1 五种基本模式

| 模式 | 特征 | 时间比 | 适用场景 |
|------|------|--------|---------|
| 场景（Scene） | 实时展开，对话+动作，1:1 时间比 | 叙述时间 ≈ 故事时间 | 冲突、对话、关键事件 |
| 概述（Summary） | 压缩时间，快速推进 | 叙述时间 << 故事时间 | 过渡、时间跳跃、背景 |
| 描写停顿（Pause） | 时间暂停，细致展开一个瞬间 | 叙述时间 >> 故事时间 | 关键物件、决定性瞬间、氛围 |
| 自由间接话语 | 叙述者和角色声音融合 | 灵活 | 角色内心冲突、认知变化 |
| 省略（Ellipsis） | 完全跳过，不叙述 | 叙述时间 = 0 | 不重要的过渡、留白 |

#### 7.2 模式切换原则

- 高潮段落：场景模式为主，关键瞬间用描写停顿放大
- 过渡段落：概述 + 省略，不浪费篇幅在非关键时间上
- 内心冲突：自由间接话语 > 直接内心独白（更自然，更像角色在"活着"而非"表演"）
- 一章中场景模式占比建议 50-70%，其余模式合计 30-50%

#### 7.3 自由间接话语示例

直接内心独白（AI 默认模式）：
> 他想，也许她说的是对的。但如果真是那样，自己这三年算什么？

自由间接话语（更自然）：
> 也许她说的是对的。那自己这三年算什么？窗外有人在叫卖糖葫芦，声音远远的。

区别：自由间接话语去掉"他想"，让角色的思绪直接流入叙述，与环境感知交织。
```

### P2-A：场景质感指导

**位置：** novel-craft §1.4 扩展为独立章节，或新增 §8 "场景质感（Scene Texture）"

**核心要点：**

```markdown
#### 场景不是布景板

**空间动力学** — 场景中的物理空间影响角色行为和选择：
- 狭小空间：压迫感，角色被迫面对面，无处可逃
- 开阔空间：暴露感，声音传不到，距离本身是障碍
- 高低差：权力隐喻，谁站着谁坐着，谁在上谁在下

**感官层叠** — 不要只用视觉。依次考虑：
- 触觉（温度、质感、重量）
- 听觉（不只是"声音"，而是声音的质地——"铁门被风吹得一下一下响，像是有人在敲"）
- 嗅觉（最强的记忆触发器——"走廊里有股消毒水味，和他小时候住院时闻到的一样"）
- 本体感觉（身体在空间中的感受——地面的倾斜、空气的湿度、海拔的变化）

**细节自证** — 好的场景细节不是装饰，它自己会说话：
- "桌上的茶已经凉了" = 等了很久
- "门没关严，能听到走廊的脚步声" = 不安全
- "花瓶换了位置" = 有人来过
```

### P2-B：情绪表达多样化

**位置：** novel-craft §4.1 扩展

在现有"可见动作 + 约束 + 微小后果"公式之外，补充 4 种替代技法：

```markdown
#### 4.1 补充：情绪表达的多种路径

"可见动作 + 约束 + 微小后果"是基础技法，但不应是唯一技法。

**感知变形** — 角色的情绪改变他对世界的感知：
> 回家的路好像比往常长了一倍。

**注意力异常** — 在重大情绪中注意到不该注意的细节：
> 她说"我们分手吧"的时候，他在数她背后墙上有几块瓷砖。

**时间变形** — 情绪改变时间感知：
> 那一巴掌落下来之前，他有充足的时间想了三件事。

**行为逻辑断裂** — 做出与情境不匹配的事：
> 听到消息的时候她正在切菜。她把菜切完了，码整齐，把刀洗干净放回去，然后蹲在地上哭了二十分钟。
```

### P3-A：质检标准重构

**核心改动：** 在 continuity-editor 的审修维度中新增"创作亮点"维度。

当前审修只有"问题"维度（FAIL/MINOR/WARNING）。新增：

```markdown
#### 亮点标注（Highlight）

审修时同时标注以下亮点（如有）：
- [VOICE] — 叙述声音有辨识度的段落
- [SURPRISE] — 角色行为/情节走向超出预期但合理的段落
- [TEXTURE] — 场景描写有质感的段落
- [DIALOGUE] — 对话呈现形式新颖的段落

亮点不影响审修结果，但写入审校报告的「## 优点」节。
```

**更重要的改动：** 调整 PASS/REVISE/FAIL 的判定逻辑。

当前：无问题 -> PASS，有 MINOR -> REVISE。
调整为：无 MINOR 且无亮点 -> 仍为 REVISE（理由："技术合规但无亮点"也需要修订）。

这是质检哲学的根本转变：**从"无缺陷即合格"到"有亮点才合格"。**

### P3-B：WritingContextPack 传递方式优化

**改动 1：新增 `tone_passage` 字段**

```json
"tone_passage": "（从前3章或参考小说中提取的1段50-100字示例文本，体现本项目的声音特征）"
```

让 chapter-writer 看到的不只是标签（`tone: "冷峻"`），而是一段**活的文本**。这段文本比 10 个形容词标签更能传递风格。

**改动 2：active_characters 补充叙事性描述**

在结构化字段之外，为每个角色附加一句叙事性的"此刻状态"：

```json
{
  "name": "张三",
  "current_goal": "找到真相",
  "fear_or_risk": "暴露身份",
  "stance": "谨慎试探",
  "speech_pattern": "...",
  "narrative_note": "他已经三天没睡了，眼窝深陷，说话时会不自觉地摸左手腕——那里有一道新伤。"
}
```

`narrative_note` 给 chapter-writer 一个"画面"而非一组"参数"，帮助它生成更有质感的文本。

### P4：项目级声音强化（长期方案）

**问题：** style_guidance 的信号量远弱于系统规则的信号量。

**方案：** 引入 `project_voice` 机制——每个项目可以定义自己的"声音覆盖"，优先级高于系统默认规则。

具体做法：
1. setup 命令在分析参考小说后，除了生成 style-guide.md，还生成 `bible/voice-profile.md`
2. voice-profile.md 包含：
   - 2-3 段该项目的"标杆段落"（从参考小说中提取或用户指定）
   - 3-5 条该项目的"声音特权"（允许该项目违反的系统默认规则）
   - 例：`本项目的声音特权：允许较高密度的修辞句（D5 门槛从 3 段连续放宽到 5 段）；允许较长的环境描写开篇（D3 不适用）；对话风格偏向裸对话（T5 无标注裸对话比例可提高到 50%）`
3. continuity-editor 预检时将 voice-profile.md 的内容注入 WritingContextPack 的 style_guidance
4. chapter-writer 看到"声音特权"后，知道在哪些维度上可以放开

这个机制的核心是：**每部小说的个性化配置可以覆盖系统默认的保守规则。**

## 第五部分：反模版化清单

### A. 一眼 AI 感的写法（chapter-writer 必须刻意避免）

| 编号 | 模式 | 为什么一眼 AI | 替代方案 |
|------|------|--------------|---------|
| T1 | 全章对话都是 `"台词。"XX说。"台词。"` | 人类作者自然混合动作先行、神态夹入、无标注对话 | 每章至少 3 种对话呈现技法 |

| T3 | 每章结尾都是"一个新信息揭示 + 角色反应" | 结尾模式固化为悬念公式 | 结尾技法库 6 种以上，当章选择与前 3 章不同 |
| T4 | 情绪全靠身体动作（攥拳、咬唇、心跳加速） | 情绪展示技法单一 | 感知变形、注意力异常、时间变形、行为逻辑断裂 |
| T5 | 全篇同一种叙述姿态（第三人称全景跟拍） | 缺少叙述模式切换 | 场景/概述/描写停顿/自由间接话语/省略交替使用 |
| T6 | 段落结构均匀（叙述-对话-叙述-对话-内心） | AI 偏好对称和平衡 | 允许不规则：连续 3 段纯对话、一整段只写一个动作、一句话独立成段 |
| T7 | 角色思考都是"他想，XXX。但是 YYY。如果 ZZZ..." | AI 的内心独白是线性逻辑推演 | 自由间接话语 + 感知碎片 + 被外部事件打断的思绪 |
| T8 | 场景描写是"视觉+声音+感觉"三件套 | 感官描写的固定模板 | 选 1-2 种非视觉感官，用独特细节承载 |
| T9 | 冲突都是"对话揭示 -> 情绪升级 -> 一方离开" | 冲突模式单一 | 静默冲突、错位冲突、行为冲突（非语言对抗） |
| T10 | 过渡段都是"时间流逝 + 简单行动 + 开始新场景" | 过渡无质感 | 用概述/省略/蒙太奇处理过渡 |

### B. 持续制造同质化的系统规则

| 编号 | 规则 | 同质化机制 | 改法 |
|------|------|-----------|------|
| S1 | 26 条反模式全量注入 chapter-writer | 认知过载导致保守写作 | 分层：核心 10 条 + 扩展 16 条（审修时用） |
| S2 | 6 道门禁硬检查 | 为通过门禁，模型走"安全路线" | 精简为 3 道 |
| S3 | blacklist 100+ 模式对写作端可见 | 写作时不应带着"禁止清单"工作 | blacklist 只注入审修端 |
| S4 | 质检标准 = "无缺陷即合格" | 鼓励保守，不鼓励精彩 | "有亮点才合格" |
| S5 | style_guidance 信号量远弱于系统规则 | 系统声音压倒项目声音 | 项目级声音覆盖机制 |
| S6 | WritingContextPack 纯结构化传递 | 角色从"活人"变成"参数" | 补充 narrative_note 和 tone_passage |
| S7 | continuity-editor 同时控制输入+输出 | 闭环收敛于合规审美 | 长期考虑分离预检和审修为两个 Agent |
| S8 | GATE-1 恒定密度要求 | 禁止节奏留白 | 放松为 500 字 + 允许标注有意减速段 |
| S9 | 结尾钩子定义只有 5 种 | 结尾自然收敛 | 扩展结尾技法库 |
| S10 | 无"正面技法词汇表" | 模型只知道避免什么，不知道可以尝试什么 | 新增对话呈现/叙述模式/情绪表达/场景质感技法库 |

### C. 创作时必须刻意执行的反模版化行为

1. **开写前检查 recent_techniques** — 确认本章开篇/结尾与前 3 章不同
2. **对话段落写完后自检** — 统计裸引号对话占比，超过 40% 则改写部分对话为其他呈现形式
3. **每章至少一处叙述模式切换** — 从场景模式切到概述、或用一段描写停顿放大一个瞬间
4. **每章至少一处"非物理动作"的情绪展示** — 感知变形、注意力异常、行为逻辑断裂任选
5. **角色首次说话时使用非裸引号技法** — 用动作先行或场景融合建立角色的"在场感"
6. **拒绝"安全选项"** — 当发现自己在写"默认模式"时（环境开篇、信息悬念结尾、攥拳表达愤怒），主动换一种方式

## 核心判断

**模型不是不会写。** Claude Opus 在无约束的创意写作中可以产出高度多样化的文本。问题在于 NarraCat 系统把一个创造性任务设计成了合规性任务。系统的每一层——从反模式到门禁到评分到审修——都在回答同一个问题："这段文字有没有犯规？"而没有人在问："这段文字有没有让人想继续读下去？"

7 部小说写出来像同一个系统的产物，不是因为模型能力不够，而是因为系统用 300+ 行规则把模型训练成了一个优秀的合规者——而合规者写出来的东西，天然就是同质的。

修复方向不是"再加更多规则"，而是**减少约束、增加技法、强化个性、奖励精彩**。
