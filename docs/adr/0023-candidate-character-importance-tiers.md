# ADR 0023: 候选角色重要度三档 —— 龙套不入池，提醒只列重要

## Status

Accepted

扩展 ADR-0015（渐进生长，候选角色池）。

## Context

写作期写手在正文里引入既有清单之外的新名字时，按 `new-character-intake.md` 契约处置；`automation_level == "auto"` 时默认全部「留作候选」。dogfood 反馈：这把**一次性龙套**（店小二、路人甲）也一律塞进候选池，导致 `/write` 收尾「一定」提醒一长串待建档角色，把真正影响剧情的角色淹没在噪声里。作者要的是「只提醒会影响剧情的重要角色」。

关键洞察：在「跳过 vs 进池」之外引入一个**静默中间档**后，真正消除噪声的开关是「提醒只列重要」，而不是「精确预测谁是龙套」——因为龙套与次要两档都不打扰作者，"会不会再出场"这种面向未来的不确定判断被化解，只剩"够不够重要到值得催建档"一个判断要做准。

## Decision

候选角色按**对剧情的影响程度**分三档，由主会话在写作期按「是否在章纲/大纲被规划 + 正文叙事权重」自动判定（写手只产纯正文、不参与判定）：

- **龙套**（只出场一次、纯功能性背景）：**不进候选池**、不铸 UID、不提醒；仅作为正文文字存在。误判可自愈——再出场时当新角色重新判定。
- **次要**（会复现但不推动主线）：进池、目录可见（带「次要」标记）、**写完正文不提醒**。
- **重要**（推动剧情 / 承担核心关系）：进池、目录可见（带「重要」标记）、**写完正文只提醒这一档**。

落地约束：

- `candidate_characters` 加列 `importance`，枚举 `minor | major`（龙套是「不写入」的结果，不占枚举值），`DEFAULT 'minor'`——旧候选与任何未显式标重要的写入一律落静默，"只在确信重要时才打扰"。
- 提醒侧过滤而非清池：`novel_list_candidate_characters` 加可选 `importance` 过滤，`/write` 收尾传 `major`；App 目录不传、取全部。
- **龙套跳过只在 write 期生效**；plan 期「被规划进大纲」本身即重要信号，不做龙套跳过。

## Considered Options

- **两档（龙套跳过 / 进池即提醒）**：否决。提醒里仍会混入「会复现但次要」的角色，不满足「只提醒重要」；且把"是不是一次性"这个面向未来的判断顶到关键路径上。
- **进池都提醒、仅按重要度排序**：否决。提醒列表照样变长，没有真正止住噪声。
- **三档 + 默认静默 + 提醒过滤（采纳）**：静默中间档化解未来不确定性；默认 `minor` 让"不打扰"成为安全兜底；过滤而非清池保留了次要角色的目录可见性与随时建档能力。

## Consequences

- 修改共享契约 `new-character-intake.md`：处置新增第 4 种结果「龙套·跳过」，明显龙套自动跳过不再逐个问；其余 register 时带 importance。
- 数据契约：`candidate_characters` 加 `importance` 列（migrate 加列，旧行落 `minor`）；register/list 工具相应扩参，upsert 用 `COALESCE` 保留既有重要度（promote 回写不清掉）。
- App 层：候选聚合与 workbench artifact 带出 importance，目录标签与引导页按档位区分展示，重要候选给「建议尽快建档」提示。
- 重要度只决定「该不该建、要不要催」，与 `profile_stage`（stub/sketch/full，衡量档案写了多少）正交，互不替代。
