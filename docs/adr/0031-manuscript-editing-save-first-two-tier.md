# ADR 0031: 正文编辑「保存永远先落盘」的两档适配

## Status

Accepted（在 [0029](0029-two-tier-editing-direct-vs-agent-cascade.md) 框架内新增正文变体；
修改「中间区优先浏览、不把编辑作默认能力」的产品基线）

## Context

正文（manuscript/*.md）与立项卡 / 章纲不同：文件本身即真相源、无字段可查表路由，
且它是记忆抽取（memory-keeper）的上游——用户手改正文不会触发任何重抽，memory.db
的 facts / 摘要 / 出场角色会静默脱节。0029 的立项卡第二档语义是「不评估就不落盘」，
照搬到正文会让作者改一句关键剧情都要等 Agent，与「花归用户」相悖。

## Decision

1. **正文获得一等编辑能力**（沉浸整章编辑，纯文本，无富文本依赖），产品基线由
   「浏览优先」改为「浏览 + 直接编辑」。
2. **保存永远先落盘**：任何评估都不阻塞写入。第二档语义从 0029 的「落盘前守门」
   变为「落盘后的记忆同步评估」（`/narracat:sync-chapter-memory`：影响报告 → 作者
   确认 → 回滚重抽本章 + arc/卷末章摘要重建 + 恢复完成进度 → 矛盾只提示不改正文）。
   **v1 仅支持同步目前完成写作的最新一章**：更早章节如实告知作者正文修改已保存、
   不受影响，引导改用重写；真单章回滚工具落地后再放开（终审发现的范围限定，见
   Consequences）。
3. **diff 分诊为确定性代码判定**（无字段表，按改动内容路由）：变更句含实体名
   （角色名 / 别名 / 短伏笔关键词，memory.db 只读取）、整段增删、变更字符超阈值
   （200，常量可调）任一命中 → 浮出第二档；全不命中 → 静默。fail-safe 偏浮出。
4. **可忽略 + 持久兜底**：作者可忽略浮出；章节挂「记忆待同步」标记（侧栏 badge +
   章节页横条）直到同步命令正常跑完。已知权衡：作者在命令内取消评估、run 正常结束
   也会清标记（可再手动发起）；机械分诊语义盲（不含实体名的事实反转会漏），由标记
   与手动入口兜底，升级路是灰区小模型分诊。
5. **`.narracat/` 新增两个 App 层自有文件**：`pending-memory-sync.json`（待同步标
   记，App 主进程独占读写）、`manuscript-edits.jsonl`（编辑 diff 留痕，声音卡进料
   口，当前只写不读）。均不属引擎契约，引擎不读写。
6. **写冲突双保险**：Agent 运行中禁用编辑入口（activeRun）+ 保存时可见正文乐观锁
   （不符即拒绝，不覆盖）；章末 chapter_metadata 注释由主进程以磁盘版拼回，渲染端
   永不经手。
7. **正文保存必须具备原子替换语义**：在同目录完成临时文件写入与 flush 后再 rename
   替换；失败时保留完整旧正文，不能留下部分正文。乐观锁与元数据保护仍先于替换执行。
8. **未保存正文是作品资产**：App 将其作为 project-local 草稿持久化在
   `.narracat/manuscript-drafts/`，随 Novel project 移动和进入废纸篓；它不进入
   NovelMemory，也不属于 Agent Core 契约。
9. **恢复必须先对基线**：草稿基线与磁盘正文一致时可直接恢复编辑；不一致时必须由
   作者选择，App 不自动覆盖。草稿只在正式保存成功或作者明确放弃后删除。

## Consequences

- 正：编辑畅通与记忆一致性解耦；分诊零成本零延迟可解释；编辑 diff 成为偏好数据
  进料口；同一「落盘后同步」模式可复用到将来角色 / 世界观自由 md 编辑。
- 成本：记忆存在「待同步窗口」，作者长期忽略标记会持续脱节（follow-up：写作流开跑
  前提示存在待同步章）；实体名信号依赖角色档案质量。
- **引擎能力缺口**：`novel_rollback_chapter` 现状按「该章及之后」区间处理（清除
  summaries / facts / 伏笔兑现动作 / 审校记录 / arc 摘要、character_cards 均按
  `>= chapter` 判定，**并连带把 `state.yaml` 的完成进度回退到回滚点之前**——
  `completed_chapters` 只保留小于回滚章的部分，须 `novel_update_progress` 恢复，
  否则引擎会把已同步的章节误判为未完成，「写下一章」时覆盖作者手改正文），**没有
  真·单章回滚**能力——同步中间章会连带清空并需重建其后所有已完成章的记忆，且无
  恢复路径。这不是本 ADR 引入的新缺口，而是既有引擎能力的边界。**正文编辑器全链
  最终审查发现本 ADR 首版命令实现遗漏进度恢复、且未收窄同步范围是两处 Critical**：
  修法为 `sync-chapter-memory` v1 仅支持同步目前完成写作的最新一章（此时回滚不再
  波及其它章节），并在命令步骤 3 显式调 `novel_update_progress` 恢复进度；真单章
  回滚是否值得投入留 follow-up（立 issue 评估，届时可放开 v1 限定）。
- **待定策略**：v1 因限定同步最新完成章，回滚不再波及其它已完成章节，「被连带
  清空的其后章节要不要自动挂待同步标记」这一待定问题在 v1 范围内不触发；若将来
  放开 v1 限定（真单章回滚落地，或决定接受区间副作用），需要一并重新评估这条策略
  （标记语义从「本章编辑触发」扩展到「被动波及」，需单独设计来源与呈现区分）。
- 关系：0029 两档 UX 契约保留（第一档=静默、第二档=评估组件浮出），本 ADR 只改正文
  的档位判定方式与第二档时序；0014（结构状态经 MCP 机械写）不受影响——重抽仍由
  memory-keeper 经提交工具完成。
- P1A 连续性增强只补正文文件与未保存草稿的耐久性，不把正文恢复扩大成整个 Novel
  project 的事务快照；已保存版本历史另作垂直切片。
