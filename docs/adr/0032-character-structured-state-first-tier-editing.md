# ADR 0032: 角色结构化状态开作者第一档直接编辑

## Status

Accepted（在 [0029](0029-two-tier-editing-direct-vs-agent-cascade.md) 框架内新增角色状态变体；
修改「角色内容全只读」的产品基线。A4×D2 片2b 随实施落定，总设计见
`docs/superpowers/specs/2026-07-13-character-entity-state-lifecycle-design.md` §6）

## Context

角色档案曾被劈成两半：文学描述 md（只读）与正文抽取的演变 facts（引擎独占写）。作者想
表达「张三现在金丹期」只能写进 md，而 md 不进 facts——记忆与作者意图结构性脱节，这是
「记忆不更新」担忧在角色上的真正落点。片1 已让角色页长出只读「状态卡 + 演变时间线」，
本决策解决「作者如何直接改」。

与立项卡（0029 第二档评估）和正文（0031 落盘后同步）都不同：角色结构化状态的修改
**波及面天然是未来**——改的是「后续写作与聊天应遵守的真相」，没有已写资产需要级联评估
（想改已写剧情本身是另一件事，是正文/章纲编辑的职权）。

## Decision

1. **状态编辑走第一档直存，不上 ImpactEvaluationDock**。两道机械轻提示代替重评估：
   编辑处展示当前值的来源与章号（「当前值：X（第N章·正文抽取）」）；set_current 携带
   `expected_current_value` 乐观锁，卡面过期即被引擎拒绝并引导刷新。计划账未来变更提示
   随片3（计划表落地）补上。
2. **写权限仍归引擎工具独占**：App 对 memory.db 与实体 json 保持零直写，经一次性 MCP
   client 确定性直调 `novel_submit_authored_state`（钦定/补录/纠错/作废/确认背书五
   action，ajv+失效链+角色卡刷新全在引擎）与 `novel_submit_character_entity`（出生证）。
   `novel_submit_authored_state` 有意不进 agent 白名单——这是作者专属入口，Agent 改状态
   必须走正文被抽取的正路。
3. **时间线编辑语义钉死为「修正记忆使其符合正文」**：改/删/补三能力编辑处固定提示
   「想改变剧情本身，请编辑正文或章纲」。原记录标失效留审计（correct 指向取代者、
   retract 复活受害行），从未生效行划线保留，不物理删除。
4. **编辑范围两级门**：维度锚定操作（直改/补录/增删项）仅词表维度可用；fact 锚定操作
   （改/删/确认）跟随快照 factId；无词表降级档（存量书）整体保持只读——与「只对新书
   生效」拍板一致。关系事实引擎工具不受理，关系区保持只读（follow-up）。
5. **出生证编辑（性别/年龄/别名）读现档全量合并后覆盖式重提交**，md 身份注释与别名行
   由引擎机械同步；App 侧绝不只传增量（引擎语义是整实体覆盖，漏传即抹字段）。改名本片
   不开（工作台 artifact 导航随迁单独切片）。

## Consequences

- 作者编辑即更新记忆：改「张三→金丹」后写下一章与聊天立即遵守，同步问题从根上消解。
- 「待确认」徽标获得出口：extracted 值轻点确认转 authored 背书，诚实标注有了处置闭环。
- 状态卡直改的生效章默认取角色卡 as_of_chapter，作者可显式调整——未来态提前钦定由引擎
  防泄露折叠兜底（event_chapter > asOf 不进当前卡）。
- 已知限制：correct 后移发生章至顶替点之后目前引擎静默 no-op（有恢复路径，拒绝守卫是
  引擎 follow-up）；关系编辑、改名、计划账轻提示、uid 合并均为后续切片。
