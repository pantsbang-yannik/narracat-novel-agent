# ADR-0034: 能力包契约——数据层行李箱 + 账房唯一选卡裁判

- 状态：Accepted（2026-07-18 产品主人批准）
- 修订：2026-07-18 v1.1——依据《能力包契约产品、运营与市场评审》（`docs/report/2026-07-18-capability-pack-product-operations-market-review.md`，Request Changes）补三 P1：双轨版本制 / 章级能力回执 / 展示边界措辞，另收敛三 P2；v1.1 已获产品主人复批（2026-07-18）

- 日期：2026-07-18

## 背景

模块二（可配置底座）要兑现「花归用户」：作者能安装、启用、导出、分享能力包（声音卡/写法卡/剧作卡/对照尺卡）。这是四泳道路线图中唯一的不可逆件——包格式一旦有用户资产落在上面就改不动了。已定死的前提：裸 prompt 市场三次证伪（包必须结构化+模型无关+可导出+署名）；账房永不可配置；社区包版权红线。

## 决策

1. **包 = manifest + 结构化卡片的数据包**（文件夹，可导出为 `.narracatpack` zip）。选卡元数据在 manifest 机械可读，卡正文渐进披露。v1 卡类型注册表：persona / craft / structure / benchmark，可前向扩展。
2. **引擎是唯一选卡裁判**：选卡打分规则、卡类型→消费方映射、投递预算全部划入账房，永不随包配置。包只带数据不带逻辑——这是防裸 prompt 坟墓的结构性保险。
3. **配置模型 = 包库全局装 + 按书启用**：启用清单落小说项目 `.narracat/packs.json`（条目 = pack id + 导入包版本锁），引擎直读；包内卡片自动分发对应 Agent，作者无需理解 Agent 分工。
4. **内置 25 项能力重组为可见官方包**（默认启用、可关但有质量警告），契约从第一天被官方包自己验证；用户将来可用自己的卡盖过官方卡。
5. **包级开关 + 自动优先级**：v1 不做卡级开关；同类卡同分裁决 user > official（> community）。origin 由安装通道决定，不信 manifest 自称。**（v1.3 修正，2026-07-20，产品主人拍板）**「同分裁决 user > official」升级为**用户卡命中即优先**（不再只在同分时靠 tie-break）：官方卡分数更高时用户卡原本永久出局，冲撞「手写一等公民」——现改为 persona（全书唯一腔调）用户卡命中即绝对优先、官方退兜底，craft（每章≤3）用户命中卡分层置顶、官方补剩余名额；只提升 `user`，`community` 与 `official` 相对关系不变；无用户命中时逐字节回落原逻辑（官方基础包等价性不破）。引擎 4.0.137，`persona-loader.ts`/`craft-pack-loader.ts`。
6. **版权红线与展示边界两条独立条款**：①版权（防机器用）——社区来源包摘录区必须为空（安装时 fail-loud 拒绝；摘录会被当范例喂进写手，他人原文会渗进下载者成稿，藏起来不能替代此条）；用户包本地自用不限，导出即按社区标准校验；官方内置包不提供导出入口；此红线 ≠ 完整版权合规，B5 开门须配举报/下架流程。②展示边界（防随手看，不承诺保密）——卡正文与摘录区是运行时数据不进 UI（v1 无卡正文查看器；官方包摘录区永不进任何展示面；将来社区包对非作者只展示简介级信息）；本地包是普通文件，明示不提供 DRM/机密性保证，不得向创作者暗示正文能保密。**（v1.2 修正，2026-07-20）**「不露正文」原文覆盖全部来源，修正为**仅覆盖非本机产物**（`imported`：导入的包，无论谁给）；例外锚**本机产物**——`created`（本机创作台发布）与刀4 的 `learned-own`/`learned-external`（从书学，学习流程打标）——由通道机械判定，正文全文可见、可复制为草稿，这是「本机可查」不是「本人作品」宣称。口径明确：不露正文是**界面降维**（防随手看、维持结果语言心智），**不是信任或安全机制**——本地文件无 DRM 是既有声明的延长线，不新增承诺；接收者的实际保护靠导出权利元数据（见决策 9 v1.2）与导入侧 lint 扫描（知情继续，不阻断）。主进程「不读 cards/ 内容」红线相应改写：**导入包侧绝对成立**（继续零读取）；**本机产物侧走显式白名单读取模块**（`electron/main/packs/pack-local-content.ts` 单一入口），审计面收窄为「查该模块调用面」，不是全面放开。
7. **云端前瞻兼容（公测后实施，契约先钉）**：包内容将上传服务器（官方包云分发、用户包云同步）；pack id+version+origin 即同步键，一切引用走 id 不走路径（包内禁绝对路径），`.narracatpack` 即上传单元。
8. **与 ADR-0020 并存不合并**：能力包=数据层（喂引擎选卡器），Skill 挂载=提示词层（挂给 Agent）。用户侧文案用结果语言（写作声音/写作手法/剧作方法/对标标准），不暴露卡类型与 Agent 分工。
9. **双轨版本制（v1.1，防连载静默漂移）**：官方内置包版本随引擎走（行为变更属引擎升级契约，变更说明随发版，回滚=回滚应用）；用户导入包按书锁 id+version、包库 `<id>@<version>` 多版本并存、默认手动升级、锁点可回退；同 id 同版本导入拒绝、新版本并存。manifest 增可选 `min_engine_version/changelog/publisher_id/license`。**（v1.2 追加，2026-07-20）**造包中心合规出口（刀3）落地最小权利元数据，manifest 再增三个可选字段：`content_hash`（包内容摘要，完整性身份）、`license`（导出确认页勾选的结果语言三选一：仅供个人使用 / 可自由分享·不可修改再发 / 可自由使用和修改，默认第二档）、`derived_from`（复制派生创作工程时自动带上的来源包 id，事后谱系证据）。均为 manifest 可选字段，契约保持 minor bump；未知字段宽容随引擎 4.0.136 回归测试锁定（`agent-core/narracat/mcp-server/src/packs/pack-manifest.test.ts`「未知顶层字段与已声明可选字段…均不报错（权利元数据向后兼容，ADR-0034）」），旧版本引擎/App 读到新字段不受影响、不报错。
10. **章级能力回执（v1.1）**：引擎构建 WCP 时同步落 `.narracat/capability-receipts/ch-NNN.json`（card_id/type/pack_id/pack_version/origin/consumer/reason + fail-soft 警告），App 折叠展示「本章使用的能力」不展示正文。回执 = 作者归因入口 + 「选卡可追溯」差异化地基 + 质量漏斗数据源（包排序不用裸安装量）。
11. **benchmark 卡 v1 仅官方来源（v1.1）**：非官方包携带的对照尺卡登记但不入对标消费，防伪造分布污染作者判断。
12. **造包中心 App 专用只读工具入契约面（v1.2 新增，2026-07-20）**：`novel_pack_authoring_vocab`（导出受控词表：情感标签/写作手法标签/结构阶段/典型情境集/典型声音画像集）与 `novel_pack_authoring_preview`（把草稿卡当 user 来源候选注入真实候选池，逐个典型情境/画像跑一遍机械选卡，只回报是否入选与理由，打分内幕不出）。二者仅供 App 造包中心编排调用，**显式排除出 agent 工具面**（`electron/main/orchestrator/sdk-runner.test.ts` 白名单 `not.toContain` 断言锁定），命名与 `novel_submit_authored_state`/`novel_resolve_planned_state` 等既有「App 直调、agent 不得调用」工具同族。选卡打分规则与投递逻辑仍完整留在引擎（决策 2 不变）——这两个工具只读不裁决，预览的是「典型场景会不会选中」而非改变选卡结果，不构成裸 prompt 坟墓的例外。

## 否决的替代方案

- 用 Skill 挂载当包载体：Skill 是提示词层，喂不进确定性选卡器，滑回裸 prompt 坟墓。
- 按 Agent 挂包：要求作者理解 5 个 Agent 分工，违反用户能力谱系低门槛端原则。
- 卡级开关：25+ 张卡的开关矩阵是负担，且关卡后质量归因困难。
- 内置能力保持隐形：契约不吃狗粮，且用户永远换不掉官方声音卡，「花归用户」打折。

## 后果

- 正：B2 官方题材包可立即开工并成为契约首次真机验证；用户资产（声音卡）与社区分享（B5）有了不可逆的落点格式；三套异构内部包路径收敛到统一候选池语义。
- 负/成本：structure 卡消费从 SKILL 固定路径改 MCP 工具化清单，是 B2 最大改动面；新 MCP 工具三处登记、双 spawn 路径 env、dist 随 src 提交等既有 footgun 全部适用；官方包重组需选卡等价性回归。
- 红线自担：官方包摘录区的去标识化纪律继续由 lint 守护；benchmark 卡只接对标报告、不接门控阈值。
- v1.1 增量成本：导入包多版本目录与锁定解析、章级回执落盘（新引擎写盘面，须过写权限隔离检查）与展示 UI——换来的是连载不漂移、能力组合可复现、选卡可追溯（后者同时是差异化卖点与质量漏斗数据源）。
- v1.2 增量成本（造包中心供给端开放，刀3）：展示边界例外扩大到本机产物、意图编译外壳+分类型预览接入两只读引擎工具、合规出口补全权利元数据字段、导入侧新增 lint 警示——换来的是创作台闭环可信（写卡→编译回显→预演→发布→分享全链有据可查）与本机内容可审计（唯一白名单入口 `pack-local-content.ts`，非全面放开）；本机产物展示边界收紧的代价由「界面降维非安全机制」口径承接，不新增保密承诺。
- 表述纪律（对外）：格式跨模型携带≠效果一致；界面不展示≠保密；卡数不是卖点；「大神文风一键复刻」禁用（详见 spec §12）；分享表述纪律延伸至造包中心制作指南——只描述自己的使用感受，不宣称对他人一定有效（v1.2，见刀2 `PackGuideView` 文案）。
