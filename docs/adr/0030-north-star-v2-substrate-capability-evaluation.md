# ADR 0030: 产品北极星 v2 —— 底座 + 能力层 + 评价层（弱模型假设退守账房层）

## Status

Accepted（2026-07-07 用户授权按总路线图全权推进；本 ADR 为路线图 M0 的立宪产物）

## Context

旧北极星建立在「按弱指令跟随假设设计」上：代码能算的绝不让 LLM 填、LLM 只产正文 + 最少判断性字段、一切结构化数据经 ajv 校验硬门把守。它成功换来了正确、一致、可控——300 章不塌的账房是真价值。但 2026-07-07 两轮诊断（一诊 `docs/report/2026-07-07-writing-quality-diagnosis.md`、二诊 `docs/report/2026-07-07-writing-quality-diagnosis-fable.md`、北极星提案 `docs/plans/2026-07-07-narracat-substrate-vision.md`）确认了三件事：

1. **两个前提过时**。写作模型（Deepseek V4 Pro 等）已不是需要关笼子的弱劳力；且整个引擎只有一套团队硬编码的创作管线，天然死板——真正能让产品开花的是用户与社区作者的创作能力，不是我们的。
2. **「冷静克制」是合规模式的文学签名**。一边写作一边跑自检清单的写手无法同时沉浸在角色的处境里（元监控与沉浸互斥）。但腔调审计同时表明病灶集中而非弥漫：outline-architect / novel-structure 已是「给作者的信」的范本，重灾区是生成端最后一公里（novel-web-craft 自检问卷）与投递接缝——**手术式修复，不是推倒重写**。
3. **旧体系缺一块承重墙：没有人回答「写得好不好」**。硬门控对主观标签做阈值判定被证伪（Goodhart + 校准噪声地板，见剧情网格「标注天花板」实测）；用户手感不可规模化。门控松绑后质量信号从哪来、未来社区能力卡怎么排序、产品岔路拿什么裁决——三问同源。

外部实证（2026-07 调研）：「超长篇一致性底座」中外均无成熟方案（Sudowrite 不保证遵守 worldbuilding、国内产品 20 章崩人设），是清晰的竞争空位；纯 prompt 分享市场（PromptBase/GPT Store）被证伪，跑通的是「挂进运行时的结构化能力」（Sudowrite Plugins / SillyTavern 卡 / Civitai 按调用分成）。

## Decision

**NarraCat 是让任何人的写作能力，都能安全地开在超长篇小说上的底座。** 系统按三层切分，每层一把尺：

| 层 | 拥有者 | 目标 | 纪律 |
|---|---|---|---|
| **账房层**（memory-keeper / continuity-editor / schema / MCP 写入口 / 一致性校验 / 目录契约） | NarraCat 团队，闭源稳固 | 300 章不塌、不矛盾、不失忆、不编造 | 旧北极星全部纪律在此继续成立并强化：确定性、ajv 校验、时序/引用/矛盾硬门。**弱模型假设退守到这一层。** |
| **能力层**（persona / 文风 / craft-pack / 大纲哲学 / 爽点 DNA） | 用户 / 社区作者，可插拔可分享 | 第一稿的阅读吸引力、灵性、说书人的声音 | 信任模型判断、喂温度而非字段、拿掉噪声。禁：自检问卷、逐条红线堆叠、克制类规训、对主观质量做硬门。 |
| **评价层**（reader-sim 模拟读者 / 头部作品分布对照 / 最终真实留存数据） | 读者（的代理） | 回答「读者会不会划走」 | **只度量、不阻断、不拥有创作**。做相对比较（A/B、对标头部分布百分位），不做绝对分数崇拜；以真实数据为终局校准。 |

一句话：**账房归我们、花归用户、尺归读者。**

派生的四条工作纪律：

1. **判断一个约束该放哪**：保「不矛盾/不失忆/不编造」（客观机械事实）→ 账房，做硬门；想控「写得好/够爽/够揪心」（主观质量）→ 创作层引导（模型+范例+persona）+ 评价层度量，绝不做硬门。
2. **账房对写作动作隐形**：一致性以「事前投递干净上下文 + 事后审校标注」兜底，不以「写作时逐条回应清单」实现。撤下的主观门以评价层报告或 continuity-editor 事后标注的形态存在，不消失。
3. **persona 是数据，不是 prompt 硬编码**：写手 agent 只保留「具身任何给定说书人身份」的壳，persona 本体作为能力卡随上下文包投递（官方卡库 → 用户/社区卡 → 用户自有文字蒸馏的声音卡）。
4. **能力卡 schema 前置约束**（为未来社区化留门，现在即生效）：模型无关、可导出、带署名字段；schema 归账房管辖（ajv 校验、版本闸门），卡内容归能力层（不审美学、只审安全）。

## Considered Options

- **维持旧北极星，继续调参修「冷」**：否决。冷是生成端合规模式的必然产出，不是渲染层 bug（ADR-0024 的关键词正向化已证明创可贴到头了）；且弱模型前提本身过时。
- **全面放开：删光门控、无脑信任模型**：否决。300 章的记忆/一致性机器是外部实证的竞争空位与护城河；罪不在账房存在，在账房范式殖民了写作路径。
- **三层切分（采纳）**：账房关笼子且对写作隐形、能力层放开且卡化、评价层补上「谁判断好」的真空。放开与开放是同一件事的两面：账房兜底，才敢让创作层交给用户。

## Consequences

- **本 ADR supersede**：`agent-core/narracat/CLAUDE.md`「运行模型 / 弱模型 prompt 纪律」中约束**创作层**的部分（改为按本 ADR 三层表述）；账房层部分原样保留。ADR-0024 的渲染层正向化在 persona 具身（路线图 S0.3）落地后由其收编。
- **执行**：总路线图 `docs/plans/2026-07-07-writing-transformation-roadmap.md`（M0 立宪 → M1 建尺+证明范式 → M2 投递翻正 → M3 岔路裁决 → M4 底座化），切片细节见 `docs/plans/2026-07-07-writing-refactor-map.md` + 二诊修正。M1 出口 GATE-1（Deepseek 真机盲评 A/B）是范式的实证闸：证伪则转电压点混合模型路线，不硬推。
- **不变的全局纪律**：不编造、写权限模型（每 agent 只持自己产物的提交工具）、运行时 prompt 出处中立、生成端零负面（负面知识下沉代码扫描——去 AI 味扫描如破折号/「不是…而是…」保留并强化，它们有生态学正当性，错的只是曾住在生成端 prompt 里）。
- **风险与刹车**：见路线图 §4（范式证伪 / 尺不准 / 门撤早了 / 社区化失焦 / 平台政策），每条有预设动作。
