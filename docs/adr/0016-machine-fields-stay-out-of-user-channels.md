# ADR 0016: 机器字段不入用户通道——结构化数据由客户端渲染

## Status

Accepted

## Context

NarraCat 已是客户端产品，作者看信息的唯一界面是两个**用户通道**：中间内容区（产物文档浏览）和右侧 Agent 对话流。dogfood 暴露大量机器字段直接泄漏到这两个通道：大纲产物里的 `F-MED-05` / `SL-01` / `V01-A01` 主键与 `major/medium` 枚举、立项卡里的 `[canon]` / `[暂定]` 确定度标记、审校报告的 `审修结果: PASS|FAIL`、对话流里的 `automation_level=auto` / 「新建模式」控制状态和 `PLUGIN_NARRACAT_NOVELMEMORY/novel_submit_chapter_outline` 原始工具名。根因：这些结构化信息以人读文本形式承载——工具渲染 markdown 时写进正文、LLM 把控制流念成人话、对话流直透技术标识。

## Decision

机器字段（主键、枚举、确定度标记、控制状态、工具标识）绝不以人读文本形式进入用户通道。它们留在结构化数据层；用户看到的是客户端对它的渲染——主键隐藏、枚举映射人话徽标、确定度渲成视觉标记、控制状态走结构化进度事件、工具名映射成面向用户的动作名。

判据（与 ADR-0015 正交）：凡是「机器需要、人不需要原文」的字段归结构化数据层、由客户端决定呈现；作者创作的散文（章节正文）保持 markdown。问题反向用法：每一处字段泄漏都指认一个该按本 ADR 结构化的环节。

## Considered Options

- **直接渲染工具产出的 markdown（含机器字段）**：否决。省事但持续泄漏，且把展示耦合到 LLM 文本格式。
- **渲染层用正则剥离机器字段**：否决。脆弱易漏，把结构语义降级成字符串清洗。
- **结构化数据层 + 客户端渲染**：采纳。机器字段留数据层、人话留渲染层。

## Consequences

- 该结构化的环节（顺字段泄漏点枚举）：大纲家族、立项卡、审校报告、角色/关系、进度状态；正文保持 markdown。
- 与切片 #238 确立的实现路径一致：主进程只读聚合 `memory.db` / `state.yaml` → 结构化快照 → 客户端渲染（主进程调不了 MCP）。
- 对话流需补「工具名/命令名 → User-facing Agent action label」映射层 + 进度走 `TaskCreate/TaskUpdate` 结构化事件。
- ID→人话映射是横切基础设施，被各产物浏览共用。枚举*定义*的 SSOT 留 agent-core schema，App 持人话*标签*并以 CI 对照测试防漂移（schema 新增枚举而 App 未映射则失败）+ 运行时未知值降级（grill #243）。
