# ADR 0024: 风格指令只承载正向写法，渲染层把「克制类校准」翻译成正向，不透传克制/留白措辞

## Status

Accepted, partially superseded（2026-07-07，by [ADR-0030](0030-north-star-v2-substrate-capability-evaluation.md) + Agent Core 4.0.74 persona 具身）

仍然有效的部分：渲染出口的克制类校准 → 正向写法翻译（数据清洗层，`positivize*` 继续运行）。被 supersede 的部分：「style_directive 是写手照做的执行字符串」这一交付框架——4.0.74 起写手以 persona（说书人身份）具身写作，style_directive 降为「该身份在本书的腔调基因」，由写手住进身份后消化，不再作为逐条执行的条款。

## Context

写手拿到的 `style_directive`（风格指令）由 `renderStyleDirective`（`mcp-server/src/handlers/readers.ts`）从立项第 8 卡「叙述声音」（`narrator_voice` 的 `tone` / `style_keywords` 等）+ `style_profile` 档位机械渲染而成（同一函数也负责叙述人称维度，见 ADR-0021）。

现状缺口（dogfood 实锤）：`narrator_voice` 卡是**作者自由文本**，当作者按文学直觉填入「克制 / 留白 / 节制抒情 / 不煽情」这类**校准措辞**时，`renderStyleDirective` 把 `tone` 与 `style_keywords` **逐字透传**进风格指令。落盘上下文包 `ch-008.json` 的真实 `style_directive` 即为证：同一段里既写「克制的冷峻」「节制抒情、留白」「关键情感节点留白不煽情」，又写「叙述不碎片化」「情绪外显、该热就热」——**自相矛盾**。在弱指令跟随假设下，重复出现的克制类强信号压倒了正向弱信号，写手倒向冷的一极，产出「凉。硬。药还在。」式的伪文学碎句、裸对话、不写表情情绪的成稿——既不是好网文，也不是好文学，丢掉了画面感与代入。

这直接违反了引擎**自己**的纪律（`agent-core/narracat/CLAUDE.md` 核心纪律）：「运行时 prompt 禁止……『克制/留白/收敛』类规训措辞——克制类校准的 4.0 解法是根本不写克制类校准」。但该纪律此前只约束**手写的** agent/skill/command prompt，管不住**经用户卡片 free-text 透传**进运行时风格指令的同类措辞——这是本决策要堵的漏洞。

「克制」本身不是要表达的目的，作者填它的**意图**（别堆砌辞藻、别滥情）是正当的；问题在于这个意图用了一个会被模型误读的词来承载。CONTEXT.md 既有术语「Scene-temperature modulation / 场景温度调制」已记录「不可把全书级冷叙误解为每个场景都用同一种短句、留白」，本 ADR 把对应的契约性约束补到风格指令这一出口。

## Decision

**`style_directive` 在契约上只表达正向写法；克制类校准措辞不得透传给写手，由渲染层在出口翻译成正向写法。**

1. **正向化翻译在渲染出口**：`renderStyleDirective` 渲染时，对 `tone` / `style_keywords` 中的克制类校准措辞（克制 / 留白 / 节制抒情 / 不煽情 / 收敛 / 含蓄 等）做正向翻译——把「别堆砌、别滥情」的正当意图翻成可执行的正向指令（如「情绪靠画面和动作演出来，不堆形容词、不空抒情」），**保留**该书的正向腔调基因（轻幽默、反讽、孤独底色等照常透传）。翻译统一在渲染出口，与 ADR-0016（机器字段/数据态不入用户通道、翻译归渲染层）、ADR-0021（`narratorAddressPhrase` 出口翻译）同模式。

2. **数据态不改、覆盖存量**：立项卡数据态（`premise.md` / `premise-cards.json`）保持作者原文不变（作者意图是 canon，不被静默改写）；正向化只发生在喂写手的风格指令出口。因此**所有现有小说无需重新立项**，下一次写作/重生即拿到干净的正向风格指令。

3. **正向功底不进生成端 prompt**：「画面感 / 代入 / show-don't-tell」等正向能力按写作质量北极星靠**喂真人范例**承载（见配套范例库改造），不在写手 prompt 里堆craft规则；反模式（碎句/裸对话/情绪标签）按「生成端零负面」走代码扫描或 /review 标注，不进生成端。本 ADR 只负责「拿掉噪声 + 正向翻译」这一环。

## Considered Options

- **正向化翻译（采纳）**：在渲染出口把克制类校准翻成正向写法，保留书的正向腔调。源头数据不动、覆盖存量、不重立项；既消除噪声又不削平书的味道。
- **直接删干净**：渲染层删掉克制类词、不替换。最简单，但会把书的腔调一并削平到档位默认，丢失作者意图里正当的部分（别堆砌、别滥情）。否决。
- **改 setup 源头（card8）不让作者填克制类词**：更彻底，但工作量大、需迁移存量小说，且把「腔调表达」与「克制校准」的边界判断推给立项对话，易误伤正当腔调描述。暂缓——可作未来增强，不改本 ADR 的「出口正向化」内核。

## Consequences

- **agent-core**：`mcp-server/src/handlers/readers.ts` 的 `renderStyleDirective` 增加克制类校准 → 正向写法的翻译；配套单测锁定「输入含克制/留白，输出为正向且不含克制类措辞，正向腔调保留」。
- **行为变更**：存量与新书的下一次写作/重生拿到的 `style_directive` 不再含克制/留白类措辞。立项卡数据态与 App 读取路径不变（沿 ADR-0008 schema 软门槛，无顶层结构变更）。
- **配套（另立 issue，不在本 ADR）**：范例选样停喂「克制/留渣」机制注解、补番茄向画面感范例进库（正向能力承载）；上下文包预算排查（避免新范例被超预算截断）；①② 验证后若碎句/裸对话仍在，再做 /review 非阻塞标注（第③刀）。
- **同域关系**：落在 ADR-0019（立项卡是引擎拥有的数据契约）内，翻译出口沿 ADR-0016 / ADR-0021；与既有术语 Scene-temperature modulation、Style directive（本次新增）对齐。
