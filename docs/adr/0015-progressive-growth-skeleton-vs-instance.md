# ADR 0015: Progressive Growth — 结构骨架前置，内容实例懒生成

## Status

Accepted

## Context

NarraCat 是超长篇（50-500 章）创作工具，且已是客户端产品。一个反复出现的设计岔路是「某类内容该在立项期一次产全，还是随剧情推进按需生成」——章细纲、角色档案、故事线都撞到它。dogfood 实测暴露了「立项期一次浇筑」的代价：plan 阶段一次产整卷章细纲（vol-01 实测一次 39+ 章）超前且易废；角色只能在 `/world` 立项期批量创建，支线角色无处安放。

## Decision

NarraCat 内容按「渐进生长」组织，分两层，判据是**是否承担跨章编排锚点职责**：

- **结构骨架层**（书级引擎 5 字段、storylines 注册表、伏笔注册表、arc 弧线）：plan 阶段**前置规划**出初始版本作为全书锚点；但**支持受控增量**——写作中加一条故事线、追加一条伏笔，经结构化提交工具显式写入并触发锚点重算，不是冻结。前置是因为跨章编排（伏笔第 18 章埋、第 65 章兑；storyline 入场/收线；arc 章范围）必须有锚点可挂，懒生成会当场击穿它。
- **内容实例层**（章细纲、角色完整档案、关系细节、章节正文）：**按剧情懒生成**，写到哪、需要到哪才具体化；支持随时新增与渐进深化（stub→full）。

## Considered Options

- **立项期一次浇筑（全前置）**：否决。超长篇前置全产章细纲/角色既超前又易废，剧情会变。
- **全懒生成**：否决。伏笔/storyline 懒生成则跨章编排无锚点，伏笔系统当场失效。
- **骨架前置 + 实例懒生成 + 骨架受控增量**：采纳。三者缺一不可——少了「受控增量」，「写作期随时加支线角色/新故事线」会和「骨架前置」正面冲突。

## Consequences

- plan 章细纲改为剧情驱动的章窗口懒生成，不再按 arc 整卷前置。
- 角色支持写作期随时新增 + 渐进深化；候选角色池接住尚未出场的角色。
- storylines / 伏笔注册表需补「写作期受控追加」入口（当前只有 plan 修改模式整体重提）。
- 与 ADR-0014（NovelMemory 机械写 structure state）协同：骨架增量经提交工具机械同步、传播锚点。
- 是裁决后续「要不要前置全产」类决策的设计公理；新环节归层时按「是否承担跨章锚点职责」判。
